근거 : SCENARIO.md 11절 (사용자 결정 11/12). 실제 실적 값 · LOT 는 저장소에 넣지 않는다.

| `pouch/v3/src/oee_pouch.js` | 파우치 라인 설정 — 부동 유형 코드 21종(알람 15 + 이상사례 5 + 기타) |

병 · PTP IDT 로 넓힐 때는 `oee_pouch.js` 와 같은 설정 파일만 라인별로 추가한다.

## 2. 데이터 항목 (대시보드 `getDashboardData()` 가 돌려주는 값과 동일)
`dateText` · `line` · `prodName` · `lotNo` · `oee` · `avail` · `perf` · `yieldRate` · `totalDown`(분) · `reason`(자유 기재) · `countermeasure` + **`reasonCode`(부동 유형 · 신규)**

- 비율 값은 0~1 또는 0~100 둘 다 받는다 (1.5 이하면 100 을 곱함).
- `reasonCode` 가 비어 있으면 `reason` 글을 낱말로 분류한다 (정확도 확인 필요 · 화면에 * 로 표시). 어느 낱말에도 맞지 않으면 '기타 · 미분류'.
- 한 기록에 코드가 여럿(쉼표 구분)이면 부동시간을 똑같이 나눈다.

## 3. 대시보드 쪽에서 추가할 것 (사용자 작업 · 확인 필요)
### 3-0. Apps Script 주소 연결 (11/16 V10 추가 → 같은 날 시험 결과 claude.ai 아티팩트에서 차단 확인 · 3-1 Drive 연결 사용)
1. 대시보드 Apps Script 의 `doGet` 맨 앞에 아래 3줄을 넣는다 (나머지는 기존 그대로).
```js
function doGet(e) {
  if (e && e.parameter && e.parameter.format === 'json') {            // IDT 용 읽기 전용 출력
    return ContentService.createTextOutput(JSON.stringify(getDashboardData())).setMimeType(ContentService.MimeType.JSON);
  }
  // … 기존 return HtmlService… 그대로
}
```
2. [배포 › 배포 관리 › 연필(수정) › 버전 : 새 버전 › 배포] — 새 버전으로 다시 배포해야 반영된다. 웹 앱 주소(…/exec)는 그대로 유지된다.
3. 웹 앱 액세스 권한 : '모든 사용자'(로그인 없이 읽기)여야 IDT 가 읽을 수 있다. 주소를 아는 누구나 실적을 읽을 수 있으므로 사내 보안 방침 확인 필요.
4. IDT › OEE › OEE 관리 대시보드 › ① 데이터 연결 › [1. Apps Script 주소 연결] 칸에 …/exec 주소를 붙여 넣고 [연결]. IDT 가 `?format=json` 을 붙여 읽고 IDT DB 에 저장한다(주소도 DB 에 저장 → 이후 열 때 30 분 경과 시 자동 갱신).
5. 실패 안내 : '웹 화면이 왔습니다' = 3줄 미추가 · 재배포 안 됨 · 권한 문제 / '연결이 막혔습니다' = 아티팩트 보안 정책 또는 사내망 차단 → 3-1(Drive 연결) 사용.
- 주소는 저장소에 넣지 않는다 (IDT DB 에만 저장).

### 3-1. 시트 연결 — Google Drive 직접 읽기 + IDT 자체 DB (11/16 V7, Apps Script 주소 방식 대체)
Apps Script 주소(…/exec)는 아티팩트 안에서 다른 사이트 호출이 막힐 수 있고 '모든 사용자' 공개가 필요해 보안상 불리하므로, **claude.ai 의 Google Drive 커넥터**로 바꾼다.

| 구분 | 내용 |
|---|---|
| 읽기 | 보는 사람의 Google Drive 권한으로 OEE 시트를 xlsx 로 내려받아 페이지 안에서 읽는다 (SheetJS · cdnjs). 머리줄 이름으로 항목을 찾고, **'포장라인' 이 파우치인 행만** 저장한다 (11/16 사용자 결정 — 계수기 · 블리스터는 저장하지 않음) |
| IDT DB | 읽은 값을 아티팩트 DB(`oee/meta` + `oee_rows/c0…`, 350 건씩)에 저장. Drive 연결이 없는 사람도 마지막 동기화 값을 본다 |
| 자동 갱신 | [OEE 관리 대시보드] 를 열 때 마지막 동기화가 30 분보다 오래됐으면 Drive 에서 다시 읽는다. DB 갱신은 쓰기 권한이 있는 사람만(개인 요금제는 소유자만) |
| 교육 기록 | 이상사례 대처 교육 결과를 `edu_log/<사용자>` 에 저장 (DB 를 쓸 수 없으면 이 브라우저에 저장) |

**사용자 작업 (1회)**
1. claude.ai › 설정 › 커넥터 에서 **Google Drive** 연결 (이미 연결되어 있으면 생략).
2. IDT 메인화면 › 과정 선택 › **OEE › OEE 관리 대시보드 › ① 데이터 연결** › [Drive 에서 찾기] (기본 낱말 `OEE`).
3. 목록에서 OEE 시트(예: '고형제포장 OEE DB')의 [이 시트 연결] → 처음 한 번 Drive 사용 허용 창이 뜨면 허용.
4. "N 건 읽음 — IDT DB 에 저장했습니다" 가 보이면 완료. 이후에는 열 때마다 자동 갱신.

**확인 필요**
- 다른 사람이 자동 갱신을 하려면 그 사람의 Drive 에서도 해당 시트를 볼 수 있어야 한다 (시트 공유). 권한이 없으면 IDT DB 의 마지막 값을 본다.
- IDT DB 의 값(LOT · 제품명 · 실적)은 이 아티팩트를 공유받은 사람 누구나 읽을 수 있다. 공유 범위를 사내 인원으로 제한할 것.
- 붙여넣기(보조) : 시트에서 머리줄 포함 범위를 복사해 붙여 넣는다. V6 까지 붙여넣기가 안 되던 원인(화면 전체 글자 선택 금지 설정이 입력칸에도 적용)을 V7 에서 고쳤다.
- 값 형식 : 비율이 % 값(예 92.5) 또는 0~1 모두 인식, `작업기간` 이 '시작일 ~ 종료일' 이면 첫 날짜를 기록 날짜로 쓴다.

## 4. 부동 유형 코드 — 파우치 라인 (11/16 실제 부동사유 기록 기준 · IDT 이상사례 대처 교육과 1:1)
사유 글은 쉼표로 항목을 나누고 항목마다 '(N분)' 을 읽어 유형별 부동시간을 더한다. 항목 앞 '충전-' · '포장-' 은 다음 항목까지 이어진다. 위에서부터 처음 맞는 유형 하나로 분류.

| 코드 | 실 | 부동 유형 (묶은 기록) | 해결법 (기록의 대책) | 중요도 (잠정) |
|---|---|---|---|---|
| RF1 | 충전 | 컨베이어 안착 불량 | 배출 슈트 각도 조정, 파우치 감지 센서 세척 · 조정 | 중 |
| RF2 | 충전 | 컷팅 불량 (컷팅 점검) | 컷팅 날 세척 → JOG 확인 | 중 |
| RF3 | 충전 | 은박 끊어짐 | 은박 교체 및 세팅 | 하 |
| RF4 | 충전 | 중량 점검 | 기록에 대책 없음 → IPC · 충전량 다이얼 조정 (확인 필요) | 상 |
| RP1 | 포장 | 정렬기 타이밍 오류 · 그룹핑 불량 | 정렬기 작동 속도 조정, 정렬부 서보모터 점검 · 교체 | 하 |
| RP2 | 포장 | 설명서 이송 불량 · 설명지 끼임 · 갈고리 휨 | 끼인 설명서 제거, 설명서 투입부 · 노즈 각도 조정 | 상 |
| RP3 | 포장 | 카토너 푸셔 오버로드 | 푸셔 CAM값 조정, 동작부 윤활유 투입, 서보모터 점검 · 교체 | 하 |
| RP4 | 포장 | 제품 투입 불량 | 카톤 성형부 조절 및 재세팅 | 중 |
| RP5 | 포장 | 카톤 클로징 | 카톤 클로징 감지 센서 세척 | 중 |
| RP6 | 포장 | 핫멜트 이상 · 인쇄부 핫멜트 튐 | 핫멜트 분사 부분 세척, 인쇄기 헤드 세척 | 상 |
| RP7 | 포장 | 소케이스 인쇄 불량 | 케이스 인쇄 헤드 세척 → 테스트 인쇄 | 상 |
| RP8 | 포장 | 충전실 안착 불량으로 인한 파우치 터짐 | 터진 파우치 제거, 배출 슈트 각도 · 파우치 감지 센서 조정 | 상 |
| ETC | - | 기타 · 미분류 | - | - |

- 기존 알람 15종 · 이상사례 5종은 교육 목록에서 삭제 (라인 가동 중 설비 인터락 알람 처리용 정의만 내부에 남김).
- 조치 위치(빨간 !)는 3D 모델 기준 추정 — 실제 조정 위치 확인 필요.

## 5. 화면 흐름 (V14)
메인화면 › 과정(충전실 · 포장실) › **[기본] [심화] [OEE]**

- OEE › **OEE 관리 대시보드** : ① OEE 현황 → ② 교육 효과 → ③ 데이터 연결.
  - ① OEE 현황 = 포장2팀 OEE 대시보드와 같은 구성 : 총 생산 배치 · 목표 95 %, 년 · 월 · 제품 필터, 관리 품목, KPI 4(시간가동률 · 성능가동률 · 수율 · OEE), 월별 OEE 트렌드(계수기 2 · 3호 / 블리스터 / 파우치), 라인별 OEE 성과 비교, 제품별 주요 부동 원인 및 대책 게시판(월 선택 시 · 제품별 최대 2건), 데이터 목록. 집계 = 기록별 값의 단순 평균(원래 대시보드와 같음). 입력 · 대책 등록은 원래 대시보드에서(IDT 는 읽기 전용). 추가로 파우치 부동 유형 순위.
  - 4개 라인 시트를 모두 IDT DB 에 저장 (11/16 사용자 결정), 교육 우선순위 · 효과는 파우치만.
- OEE › **이상사례 대처 교육** : 충전실 4 · 포장실 8 사례, 우선순위 = 0.4 × 부동시간 + 0.3 × 발생 횟수 + 0.3 × 중요도 등급.
- 예시 데이터는 규칙으로 만든 값이며 화면에 '실제 실적 아님' 을 표시한다.
- 한계 : 교육 효과는 기록이 쌓여야 비교되고, 품목 · 정비 등 다른 요인의 영향은 구분하지 않는다.
