## 2. 구조 (안)
- 셸 = 파우치 엔진(Three.js r147 · 파우치 재질 · 작업자 human.js) — PTP(ptp3) 셸 구조를 재사용
- 충전실 : 기존 병 IDT(`bottle/src`)의 형상 함수(engine.js 의 Sink 버퍼 p/n/c)를 매 프레임 Three.js 로 옮겨 그림 (PTP 형상 다리와 같은 방식) · 과정 · HMI · 시뮬레이션은 원본 그대로
- 포장실 : 새로 모델링 (턴테이블 · 라벨 인쇄기 · 라벨러 · 비전 · 리젝터 · 설명서 부착기 · 중량선별기 · 작업대 · 판독대 · AG 라벨 프린터 · 박스 작업대 · 파렛트) + 포장 시뮬레이션 · 화면 · 과정은 새로 작성
- 두 실 사이 : 벽 통과구 컨베이어(충전실 집적 테이블 → 포장실 턴테이블)

## 3. 단계

|---|---|---|

| B2 | 포장실 설비 모델 · 병 흐름(통과구 → 턴테이블 → … → 작업대) | 사진과 같은 배치 · 병이 흐름 |
| B3 | 포장 시뮬레이션 · 설비 화면(인쇄기 · 라벨러 · 설명서 컨트롤러 · 중량선별기 · 집합 포장 PC) · 리젝트 · 자재 소모 | 리젝트 · 소모 · 카운트 동작 |

## 4. 추가 결정 (11/18 사용자)
- 파렛트 적재 단수 · 박스 크기 · 포장실 장비 치수 : 현실에서도 품목마다 다르므로 IDT 에서 정함 (사진 어림값 기준)
- 판독 불가 · 중복 판독 : 리젝트 → 라벨만 제거한 뒤 병은 다시 턴테이블로 (재작업 경로)
- 비전 PC 화면 · 라벨 인쇄기 화면 · 라벨러 판넬 · 설명서 부착기 : 작업자 조작은 ON/OFF 만 (설명서 부착기는 화면 없이 하드웨어 버튼 · 램프만) · 중량선별기는 중량 세팅(기준 · 상하한)과 RUN/STOP (인쇄 내용은 작업 데이터로 들어옴 → IDT 에서 제조번호 · 사용기한 입력 단계 없음, 첫 인쇄 대조는 유지)
